# Deployment Guide

## Prerequisites

- Node.js 20+
- npm 10+
- Azure subscription with an Azure Static Web Apps resource
- GitHub repository connected to the project
- An Azure Static Web Apps deployment token stored as the GitHub Actions secret `AZURE_STATIC_WEB_APPS_API_TOKEN`

## Local production build

1. Install dependencies with `npm ci`.
2. Copy `.env.production.example` to `.env.production` if production defaults need to be overridden.
3. Run `npm run lint`, `npm run type-check`, `npm run test:unit`, and `npm run build`.
4. Serve `dist/` with a static HTTP server and verify SPA navigation.

Never commit real credentials or secrets. Variables prefixed with `VITE_` are bundled into browser code and must be treated as public.

## GitHub Actions deployment

The `build-deploy.yml` workflow validates the application before deployment.

For main-branch pushes:
1. Checkout the repository.
2. Install dependencies.
3. Run lint, formatting, type checking, unit tests, E2E tests, and production build.
4. Deploy `dist/` to Azure Static Web Apps.

Required repository secret:

- `AZURE_STATIC_WEB_APPS_API_TOKEN`: deployment token generated by the Azure Static Web Apps resource.

Pull requests run the validation/build job but do not deploy to production.

## Rollback

The safest rollback is to revert the problematic main-branch commit and allow CI to deploy the resulting known-good commit.

If the Azure resource itself is misconfigured, disable the deployment workflow temporarily and use the Azure portal deployment history to identify the last healthy deployment.

## Monitoring and error tracking

Client-side runtime and performance diagnostics are available through:
- `src/utils/errorTracking.ts` for the last 50 tracked errors.
- `src/utils/performanceMonitor.ts` for performance metrics and slow-operation diagnostics.

These records are local browser diagnostics; they are not a replacement for a centralized telemetry service.

## Troubleshooting

### Blank page after deployment
Check browser console, verify `staticwebapp.config.json` is included in the deployed site, and confirm SPA fallback routes to `/index.html`.

### Deployment authentication failure
Verify the `AZURE_STATIC_WEB_APPS_API_TOKEN` secret exists and was copied from the intended Static Web Apps resource.

### Build passes locally but fails in Actions
Use the same Node.js major version (20) and run `npm ci` rather than `npm install`.

### Unexpected cached assets
The deployment config applies long-lived caching to fingerprinted assets. If an old asset persists, verify the generated asset filename changed with the new build.
